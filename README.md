# 係の履歴書メーカー（AI Handbook メーカー）

OpenPNE に AI を「係」として迎え入れるための、小さな静的 Web アプリです。
AI の行動指南書「AI Handbook」の1章（例：翻訳係、Tips係）を、日本の履歴書の形をした **A4・1枚の PNG 画像「係の履歴書」** にまとめます。

- **表（見た目）**：Handbook の全文を、人間にも AI にも読める履歴書のレイアウトで載せます。
- **裏（埋め込みデータ）**：同じ内容を機械で読める JSON にして PNG の中に入れます。

受け取った人は、自分の Claude に画像を読ませて係を「採用」（自分の SNS に導入）できます。

**公開ページ：** https://tejima.github.io/op4-resume/

## 使い方

`index.html` をブラウザで開くだけで動きます（サーバーもビルドも不要）。GitHub Pages にそのまま置けます。
すべての処理はブラウザの中で完結し、入力内容や画像を外部に送信しません。日本語フォント（Noto Sans JP）だけは Google Fonts から読み込みます。

### 作るモード

1. 左のフォームに各欄を入力します（「サンプルを読み込む」で翻訳係・Tips係の例を読み込めます）。箇条書きの欄は **1行に1項目** です。
2. 右のプレビューに A4 の履歴書がその場で描かれます。
3. 「PNGで保存」で `kakari_<係名>_<版>.png` を書き出します。

| ボタン | はたらき |
|---|---|
| PNGで保存 | 裏データ入りの履歴書 PNG を書き出す |
| Handbookテキストをコピー | 下の「テキスト形式」でクリップボードにコピー（OpenPNE の日記にそのまま貼れる） |
| Handbookテキストから読み込む | テキスト形式を貼り付けて各欄に分解する |
| JSONで保存 ／ JSONから読み込む | 下書きの保存と再編集 |
| サンプルを読み込む | 翻訳係・Tips係のサンプル |
| クリア | 入力をすべて消す |

- 入力途中の内容はブラウザ（localStorage）に自動保存されます。
- 文字数・項目数が上限を超えたとき、または全文が1枚に収まらないときは警告が出て、PNG の保存ボタンが押せなくなります（文字を小さくして詰め込むことはしません）。
- アイコン画像は PNG / JPEG / WebP だけ使えます（SVG は使えません）。正方形に切り抜いて 512×512 にします。

### 読むモード

係の履歴書 PNG をドラッグ＆ドロップ（またはファイル選択）すると、裏データを取り出して表示します。

- 係名・版・作者・絵師・ライセンス・作成日時
- Handbook 全文（コピーボタンつき）
- アイコン画像（512×512 PNG で保存できます）
- 整合性チェックの結果
  - **一致**：表と裏は同じ元データから作られています
  - **不一致**：裏データが改変されている可能性があります
  - OpenPNE認定：未認定（電子署名は今後の予定）
- 「作るモードで開く」で、その内容を編集に使えます。

SNS にアップロードすると PNG の埋め込みデータが消えることがあります。そのときは「この画像には裏データがありません…」と表示されるので、履歴書の表面を Claude に読ませて取り込んでください。

> 係の履歴書の中身は、AI への指示書です。採用する前に、必ず運営者が全文を読んで確認してください。

## 欄の対応

| データ項目（Handbook） | JSON のキー | 履歴書の欄名 | 形式 | 上限 |
|---|---|---|---|---|
| 係名 | `kakari.name` | 氏名 | 1行 | 20字 |
| 版 | `kakari.version` | 氏名の横 | 1行 | 10字 |
| 目的 | `kakari.purpose` | 志望動機 | 複数行 | 120字 |
| できること | `kakari.abilities` | 得意なこと | 箇条書き | 5項目・各40字 |
| きっかけ | `kakari.triggers` | 勤務時間 | 箇条書き | 3項目・各40字 |
| 担当範囲・設定 | `kakari.scope` | 勤務地 | 複数行 | 150字 |
| 使う手足 | `kakari.tools` | 使う道具 | 箇条書き | 6項目・各30字 |
| 手順 | `kakari.steps` | 仕事の進め方 | 番号付き | 8項目・各80字 |
| やらないこと | `kakari.donts` | 誓約事項 | 箇条書き | 8項目・各60字 |
| 困ったとき | `kakari.troubles` | 困ったときは | 箇条書き | 4項目・各80字 |
| 出力の例 | `kakari.example` | 仕事の見本 | 複数行 | 250字 |
| うまくいったかの見方 | `kakari.evaluation` | 評価のしかた | 箇条書き | 3項目・各50字 |
| Handbook作者 / 絵師 / ライセンス | `credits.*` | 推薦者 | 1行・選択 | 30字 |
| アイコン画像 | `icon` | 写真 | 画像 | 512×512 |

各欄の上限は目安です。すべての欄を上限まで埋めると1枚に収まらないため、実際には「1枚に収まるか」の判定もあわせて行います。

## データ形式

### 履歴書 PNG の裏データ（formatVersion 1）

- PNG の `iTXt` チャンク（UTF-8・非圧縮）に、キーワード `openpne-handbook` で JSON を入れます。
- チャンクは `IEND` の直前に置きます。CRC32 は自前で計算しています（外部ライブラリなし）。
- 画像は 1240×1754 px（A4・150dpi 相当）。

```json
{
  "format": "openpne-handbook",
  "formatVersion": 1,
  "kakari": {
    "name": "翻訳係",
    "version": "v1.0",
    "purpose": "...",
    "abilities": ["..."],
    "triggers": ["..."],
    "scope": "...",
    "tools": ["..."],
    "steps": ["..."],
    "donts": ["..."],
    "troubles": ["..."],
    "example": "...",
    "evaluation": ["..."]
  },
  "credits": {
    "author": "...",
    "illustrator": "...",
    "textLicense": "CC BY 4.0",
    "imageLicense": "..."
  },
  "handbookText": "（下のテキスト形式の全文）",
  "icon": "data:image/png;base64,...",
  "createdAt": "2026-10-27T12:00:00+09:00",
  "hash": "sha256:...",
  "signature": null
}
```

| キー | 説明 |
|---|---|
| `kakari` | Handbook の各欄。箇条書きは文字列の配列、それ以外は文字列（複数行は `\n` 区切り）。空の欄は `""` か `[]` |
| `credits` | クレジット。未設定は `""` |
| `handbookText` | `kakari` と `credits` から作ったテキスト形式の全文 |
| `icon` | 512×512 のアイコン。`data:image/png` が基本で、大きな写真のときは `data:image/webp` または `data:image/jpeg`。なければ `null` |
| `createdAt` | 書き出した日時（ISO 8601、時差つき） |
| `hash` | 下記のハッシュ |
| `signature` | 将来の「OpenPNE認定」（電子署名）用の予約欄。現在は常に `null` |

**ハッシュの計算方法**

1. `{ "kakari", "credits", "handbookText", "icon" }` の4つだけを取り出したオブジェクトを作る（`icon` がなければ `null`）。
2. すべての階層でキーを文字コード順に並べ、空白なしで JSON にする（配列の順番はそのまま）。
3. その UTF-8 バイト列の SHA-256（Web Crypto API）を16進で書き、先頭に `sha256:` をつける。

読むモードでは次の3つを確かめ、すべて通ったときだけ「一致」と表示します。

- PNG のすべてのチャンクの CRC が正しく、構造が壊れていないこと
- `hash` が再計算した値と同じであること
- `handbookText` が `kakari`・`credits` から作り直したテキストと同じであること

表面の画像は、書き出しのたびにこの JSON と同じ元データから描いています。表だけを書き換える経路はありません。

### Handbook のテキスト形式

「Handbookテキストをコピー」で出力し、「Handbookテキストから読み込む」で解析する形式です。OpenPNE の日記に貼って AI に読ませることを想定しています。

```
【AI Handbook：<係名>】<版>

■ 係の名前と目的
<係名>。
<目的>

■ できること
・<項目>

■ きっかけ
・<項目>

■ 担当範囲・設定
<内容>

■ 使う手足
・<項目>

■ 手順
1. <項目>

■ やらないこと
・<項目>

■ 困ったとき
・<項目>

■ 出力の例
<内容>

■ うまくいったかの見方
・<項目>

■ クレジット
Handbook作者：<作者>
絵師：<絵師>
ライセンス：テキスト <テキストのライセンス> ／ 画像 <画像のライセンス>
```

- 空の欄は見出しごと省略します。クレジットも、空の行は省きます。
- 解析は `■` の見出し単位です。全角・半角スペースや空行の有無の揺れは許容します。箇条書きの記号は `・` `-` `*` `•`、番号は `1.` `１．` `1)` などを受け付けます。
- 知らない見出しは読み飛ばします（読み込み時に通知します）。
- 「■ できること」は、指示書の初版のテキスト形式にはなかった見出しです。JSON と履歴書の「得意なこと」欄との往復のために加えています。

## ファイル構成

```
index.html          アプリ本体（HTML / CSS / JavaScript）
samples.js          サンプルデータ（翻訳係・Tips係）
samples/            サンプルの書き出し PNG
tests/roundtrip.js  往復テスト（ヘッドレス Chromium）
```

`index.html` の中の JavaScript は役割ごとに分けてあり、`window.KakariResume` から使えます。係図鑑や OpenPNE 認定を後から足すときは、これらを使い回せます。

| モジュール | 役割 |
|---|---|
| `Handbook` | 欄の定義・正規化・文字数チェック |
| `HandbookText` | テキスト形式の出力と解析 |
| `PngChunks` | PNG チャンクの読み書き、iTXt、CRC32 |
| `Record` | 裏データ JSON の組み立て・ハッシュ・検証（`signature` の検証はここに足す） |
| `Icon` | アイコン画像の読み込み・切り抜き・形式判定 |
| `Resume` | 履歴書の表面を Canvas に描く（プレビューと書き出しで共通） |
| `Exporter` | 元データ → 表面 → PNG → 裏データ埋め込み |
| `App` | 画面 |

## テスト

```sh
npm install playwright   # 未導入なら
npx playwright install chromium
node tests/roundtrip.js
```

サンプル2件を書き出して `samples/` に保存し、読むモードで往復できること、1バイトの書き換えや JSON の改変を見つけられること、SVG を拒否すること、ファイルサイズなどを確かめます。
